## 🌟 Overview

**WeddingHall** is a Windows-desktop **booking-management system** for wedding halls and event venues, built with **C# / Windows Forms** on **.NET Framework 4.5**.

It uses a **Microsoft Access (`.accdb`)** database (`login.accdb`) connected through **OLE DB (Microsoft.ACE.OLEDB.12.0)**. The app ships with two tables:

- 🔐 **`Table1`** — login credentials (`UserName`, `Password`).
- 📒 **`BookingData`** — full booking records (event info + customer info + payment info).

Once logged in, an admin can **create new bookings**, **view / update / search** existing bookings in a `DataGridView`, **record advance & remaining payments**, and **search halls by capacity**. The app also bundles a **strongly-typed `loginDataSet1.xsd`** for designer-level data binding.

## ✨ Features

- 🏠 **Splash / landing screen** (`Form1`) with branded UI and a confirmation dialog before exit.
- 🔐 **Login** (`Form2`) — verifies the entered username & password against `Table1` in `login.accdb`.
- 🧭 **Dashboard** (`Form5`) — central hub with quick access to *New Booking*, *Booking Info* and *Logout*.
- 📝 **New Booking** (`Form3`) — capture **Name, Phone, Address, Email, City, Event Date, Event Session, Event Type, Number of Guests, Assigning Hall, Advance Payment, Total Amount**, and insert into `BookingData`.
- 📋 **Booking Info** (`Booking Info 2`) — load all bookings into a `DataGridView`, click a row to load it into editable fields, then **update** (`UPDATE BookingData SET … WHERE ID =`).
- 🔄 **Reset / Clear** menu item to wipe the form fields back to a clean state.
- 💳 **Payment Info** (`Payment Info`) — pick a booking by ID, see **Total / Advance / Remaining**, accept a new payment, recompute the new advance & remaining amounts, and update the row.
- 🔍 **Hall Search** (`search`) — filter bookings/halls by **capacity** with an `OleDbDataAdapter` → `DataGridView`.
- 🧱 **Strongly-typed dataset** (`loginDataSet1.xsd` + `BookingDataTableAdapter`) generated by the Visual Studio Dataset Designer for designer data-binding.
- 🖼️ **Class diagram** (`ClassDiagram1.cd`) included for documentation.
- 🪟 Centralized **`App.config` connection string** (`Restaurant_Management_System.Properties.Settings.loginConnectionString`).

## 🗄️ Database

The app talks to **`login.accdb`** through OLE DB. The connection string in `App.config` is:

```xml
<add name="Restaurant_Management_System.Properties.Settings.loginConnectionString"
     connectionString="Provider=Microsoft.ACE.OLEDB.12.0;Data Source=|DataDirectory|\login.accdb"
     providerName="System.Data.OleDb" />
```

> ⚠️ Several forms (`Form2`, `Form3`, `Booking Info 2`, `Payment Info`, `search`) currently use a **hard-coded** connection string pointing at `C:\Users\hp\Documents\login.accdb`. Update those to `|DataDirectory|\login.accdb` (or your own path) before running.

## ⚙️ Setup & Run

### 1️⃣ Clone

```bash
git clone https://github.com/ahmadimran-15/WeddingHall-Booking-WinForms.git
cd WeddingHall-Booking-WinForms
```

### 2️⃣ Install the Access Database Engine

Download **Microsoft Access Database Engine** from Microsoft and install the **same bitness** as your project (Project → Properties → Build → *Platform target*: `x86` or `x64`). Without it you’ll get a `'Microsoft.ACE.OLEDB.12.0' provider is not registered on the local machine` error.

### 3️⃣ Fix the hard-coded paths

The bundled forms reference an absolute path:

```csharp
@"Provider=Microsoft.ACE.OLEDB.12.0;Data Source=C:\Users\hp\Documents\login.accdb;Persist Security Info=False;"
```

Either:
- copy `login.accdb` to `C:\Users\hp\Documents\login.accdb`, **or**
- (recommended) do a global find & replace in the project so each form reads:

```csharp
@"Provider=Microsoft.ACE.OLEDB.12.0;Data Source=|DataDirectory|\login.accdb;Persist Security Info=False;"
```

The project already copies `login.accdb` to the output directory, so `|DataDirectory|` resolves to `bin\Debug\` at runtime.

### 4️⃣ Open in Visual Studio

Double-click **`Restaurant Management System.sln`**, then hit **▶ Start** (F5).

## 📲 Using the App

1. 🚀 Launch the app — the **splash / landing screen (`Form1`)** opens. Click *Login*.
2. 🔐 In **Form2**, enter the username & password stored in `Table1` of `login.accdb`. On success you’re sent to the dashboard.
3. 🧭 From the **Dashboard (`Form5`)** you can:
   - 📝 Open **New Booking** (`Form3`) and fill in customer + event + hall + payment fields → **Save** runs an `INSERT INTO BookingData …`.
   - 📋 Open **Booking Info** (`Booking Info 2`), click **Load** to populate the `DataGridView` from `BookingData`, click any row to push values into the editable fields, edit, and **Update**.
   - 💳 Open **Payment Info**, search by booking **ID**, see **Total / Advance / Remaining**, type a new payment and **Save** — the app recomputes:
     - `new advance = current advance + payment`
     - `new remaining = current remaining − payment`
     - shows *“Amount paid”* if remaining hits 0, otherwise *“Amount is not fully paid”*.
   - 🔍 Open **search** to filter halls/bookings by **Capacity**.
4. ❌ Closing the main window prompts: *“Do you really want to close Wedding Hall Management System Application?”*

## 🧰 Troubleshooting

| 🚧 Problem | 💡 Fix |
|---|---|
| `'Microsoft.ACE.OLEDB.12.0' provider is not registered on the local machine` | Install the **Microsoft Access Database Engine Redistributable** with the same bitness as your build (x86 vs x64). |
| `Could not find file C:\Users\hp\Documents\login.accdb` | Either copy `login.accdb` to that path, or replace the hard-coded connection string in each form with `|DataDirectory|\login.accdb`. |
| `The Microsoft Access database engine cannot open or write to the file…` | Close any other process holding the `.accdb` open (Access, another instance of the app), and check NTFS permissions on `bin\Debug\login.accdb`. |
| Login always says *invalid* | Verify a row exists in `Table1` with matching `UserName` / `Password` (the comparison is case-sensitive). |
| Build target framework not installed | Install the **.NET Framework 4.5 Developer Pack**, or right-click the project → *Properties → Application → Target framework* and bump it to a version you have. |
| Build error: `Microsoft.CSharp` / `System.Net.Http` missing | Restore default references (those are listed in the `.csproj`); reinstall the **.NET Framework targeting pack**. |
| `Data type mismatch in criteria expression` on update | Numeric columns (`AdvancePayment`, `TotalAmount`, `RemainingAmount`) are `Integer` in Access — make sure your text boxes parse to numbers before the SQL runs. |

## 🌱 Future Improvements

- 🛡️ **Parameterize every query** — current `INSERT` / `UPDATE` / `SELECT` statements are built with string concatenation and are vulnerable to SQL injection.
- 🔒 **Hash passwords** instead of storing plain text in `Table1`.
- 🧱 Use the **`App.config` connection string** everywhere (drop the hard-coded `C:\Users\hp\Documents\login.accdb`).
- 🧹 Rename `Form1`/`Form2`/`Form3`/`Form5` to descriptive names (`SplashForm`, `LoginForm`, `NewBookingForm`, `DashboardForm`).
- 🧪 Add **unit tests** around payment math (advance / remaining recalculation).
- 🧾 Add **PDF / printable invoice** generation for each booking.
- 📅 **Hall-availability check** on the booking date before insert (prevent double-booking).
- 📈 Add a **dashboard** with daily / monthly bookings and revenue totals.
- 🌍 Migrate to **.NET 8 + WPF / WinUI** with **SQLite** or **SQL Server** for a modern, multi-user setup.
- 🌗 **Dark theme** + responsive layouts for high-DPI monitors.
